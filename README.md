# BLACK 21 — Casino Night

Мобильное табло и учёт игрового капитала для вечеринки на **23 участника**. Проект использует Node.js без внешних зависимостей, сохраняет данные в JSON на диске и обновляет публичные рейтинги каждые 2,5 секунды.

## Возможности

- **Общий лидерборд:** текущий капитал за вычетом непогашенного игрового кредита.
- **Лидерборды отдельных игр:** Texas Hold'em, Blackjack, Craps и Roulette, сортировка по **чистому выигрышу** за всё мероприятие.
- **Бонусы за активности:** отдельный рейтинг, лимит 700 $ на участника.
- **Админка:** результаты до 23 игроков в одной операции (плюс и минус), массовый импорт списка гостей, кредиты, поправки, история и отмена ошибочных записей обратной проводкой.
- **Разные администраторы:** логин/пароль с hash (scrypt), владелец назначает/удаляет доступы, все операции сохраняют автора и время.
- **Касса:** доменный баланс казино, персональный резерв наград, общий кредитный фонд и предупреждение при превышении доступного обеспечения.
- **Сохранение структуры существующего проекта:** старые профили из data/participants.json читаются, прежний числовой score учитывается как историческая корректировка.
- **Без реальных денег** — все номиналы игровые.

## Быстрый запуск

Требуется Node.js 20+ (рекомендуем 22).

Первый запуск **обязательно** с паролем организатора, длина не менее 12 символов:

### Linux / macOS
```sh
ADMIN_USERNAME=owner ADMIN_PASSWORD='ПРИДУМАЙТЕ_СВОЙ_ДЛИННЫЙ_ПАРОЛЬ' node server.js
```

### Windows PowerShell
```powershell
$env:ADMIN_USERNAME="owner"
$env:ADMIN_PASSWORD="ПРИДУМАЙТЕ_СВОЙ_ДЛИННЫЙ_ПАРОЛЬ"
node server.js
```

После первого запуска аккаунт сохраняется в data/admins.json; пароль больше не нужен в окружении для последующих перезапусков. Для публичного доступа используйте HTTPS-реверс-прокси (Caddy или Nginx). За HTTPS установите COOKIE_SECURE=1. **Не выставляйте пароль или data/admins.json в GitHub и не используйте простой HTTP в интернете.**

Адрес: http://127.0.0.1:4173. Порт можно менять переменной PORT.

Параметры:
- ADMIN_USERNAME и ADMIN_PASSWORD — первичная настройка владельца.
- COOKIE_SECURE=1 — обязательно за HTTPS-прокси.
- REGISTRATION_CODE=секрет — включает добровольную самостоятельную регистрацию по приглашению; без значения добавлять участников могут только администраторы.
- DATA_DIR=/persistent/data — расположение постоянного хранилища на диске (опционально).
- PORT=4173 — порт сервера.

### Что нужно сделать перед вечеринкой

1. Открыть #admin, войти как владелец.
2. Добавить участников вручную либо вставить список **«Имя; серийный номер»** (23 строки максимум). Никакие частные списки гостей в публичный GitHub автоматически не публикуются.
3. Назначить помощников через блок «Назначенные администраторы», передать им уникальные логины и пароли.
4. Убедиться, что у всех одинаковый стартовый капитал 1800 $ и у каждого личный резерв бонусов 700 $.
5. Провести пробную покерную транзакцию и отменить её (проверить сумму=0 и журнал).

## Правила учета

**Валюта:** 1 бумажный игровой доллар = 1 фишечный доллар. Размен банкнот на физические фишки **не изменяет** общий баланс игрока, поэтому такой размен не нужно записывать как заработок/проигрыш. Переходящие между гостями именные бумажные купюры отражайте только при реальном изменении индивидуальных балансов; лица на банкнотах не означают текущего владельца.

- **Старт:** 1800 $ на человека. Создание 23 профилей устанавливает общий начальный капитал 41400 $.
- **Активности:** по 700 $ ещё не выданных именных денег на человека, каждая выплата учитывается с категорий «Активности». Система не разрешит выдать одному человеку больше 700 $.
- **Покер:** администратор записывает выигрыши (+) и проигрыши (−) одновременно, по столу/раунду, причем сумма изменений **строго 0**. Это предотвращает случайное создание новых денег.
- **Блэкджек, крэпс, рулетка:** админ вводит чистый результат гостей; банк автоматически получает противоположную сумму. Пример: выигрыш +175 $ уменьшает баланс казино на 175 $.
- **Кредиты:** до 500 $ каждому и суммарно до 2000 $ непогашенных на весь вечер. Выдача в операциях категории «Кредит» со знаком +, возврат со знаком −. Долг вычитается из общего лидерборда.
- **Корректировки:** отдельный вид операции с обязательной причиной. Они влияют на счет банка, поэтому используйте для исправлений или организаторских проводок осознанно.
- **Отмена:** сохраняется исходная запись и добавляется обратная. Отмена может быть отклонена, если выигранные деньги уже потрачены и обратная запись сделает баланс отрицательным.

Касса стартует с **1450 $** свободного обеспечения, исходя из 58 950 $ номинала физических фишек минус 23 × (1800 + 700). Если обязательства превысят обеспечение, админка покажет предупреждение; это не автоматический выпуск новых денег. Рекомендуется контролировать предел выплат перед каждым спином рулетки и большой раздачей блэкджека.

## Маршруты

- /#leaderboard — публичное табло (выбор игры)
- /#register — регистрация по коду, если включена
- /#admin — вход, операции, участники, сотрудники
- GET /api/state — публичные агрегированные показатели без секретных токенов
- POST /api/admin/login, GET /api/admin/me, POST /api/admin/logout — админская сессия
- GET/POST /api/admin/transactions — журнал и записи
- POST /api/admin/transactions/reverse — аудируемая отмена
- POST /api/admin/participants и /api/admin/participants/bulk — гости и импорт
- POST /api/admin/accounts, POST /api/admin/accounts/revoke — доступы (только владелец)

## Сохранность данных и безопасность

- Источник истины на сервере: data/participants.json, data/transactions.json, data/admins.json. Два последних файла и новые фото исключены из Git.
- Сделайте резервную копию этих файлов до старта и после каждого этапа. Для публичного сервера нужен **постоянный диск**; обычные serverless-инстансы с эфемерной файловой системой не подходят без внешней БД.
- Сессии хранятся в памяти: после перезапуска администраторы входят заново.
- Ограничение попыток входа, HttpOnly и SameSite=Strict cookie, проверка Origin, проверка на отрицательные балансы.
- Старый репозиторий исторически содержал тестовые профили и регистрационные токены в tracked JSON. Новая версия не использует эти токены для доступа и не возвращает их публично. Удалять файл из работающего развёртывания без бэкапа нельзя.
- Редактирование файлов через pull request не обновляет автоматически работающий сервер. После merge необходимо обновить сервер и перезапустить процесс.
